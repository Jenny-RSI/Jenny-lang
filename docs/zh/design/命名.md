# 语言的命名
**Spinning Jenny（珍妮纺纱机，简称 Jenny）** 

### **一、 为什么“Jenny”与这门语言的灵魂完美契合？**

> 1. **从“单锭手工”到“多锭协同”的历史隐喻**：  
   * 1764 年哈格里夫斯发明珍妮纺纱机之前，纺工一次只能摇动一个纺锤纺一根线（就像今天程序员一行行手敲 C++/Rust 的生命周期和模板）。  
   * 珍妮纺纱机第一次让**一个人的双手可以同时驱动多个纱锭（Spindles）**，拉开了第一次工业革命的序幕。  
   * 而在今天的 **AI 工业革命开端**，**Jenny 语言** 正是为“人类 \+ AI 协同纺纱”而生：人类掌控核心架构之轮，AI 与 @meta 引擎同时驱动多条代码生成纺锤，将生产力推向新的纪元。  
> 2. **双股合捻（Two-Ply Twisting）：\*T 与 ^T 的绝妙意象**：  
   * 纺纱的核心工艺是将不同特质的纤维拧合（Twist）成一根既柔韧又强固的纱线。  
   * 在 **Jenny** 语言中，**\*T（原生堆指针）** 是坚韧的**亚麻经线（Warp）**，提供直通 C 语言与硬件的刚性骨架；**^T（GC 托管句柄）** 是轻盈柔顺的**棉毛纬线（Weft）**，提供高层业务的极致弹性。两者在 Jenny 编译器中合捻为一。  
> 3. **拟人化与 AI 时代的亲和力**：  
   * 当开发者对 AI 助手说 *“Write this module in Jenny”* 或在命令行输入 jenny run 时，它不再是一个冰冷的缩写（如 GCC、LLVM、Rust），而像是在呼唤一位聪明、严谨、懂你的工程伙伴。

### **二、 Jenny 语言全套工程命名体系（Toolchain & Ecosystem）**

围绕 **Spinning Jenny** 的纺织与工业革命母题，我们可以把整个编译器、包管理器、元编程与并发原语命名得极具诗意与统一感：

| 核心组件 / 概念 | 命名方案 | 灵感与工程含义 |
| :---- | :---- | :---- |
| **语言全称 / 简称** | **Spinning Jenny** / **Jenny** | 致敬工业革命起点，开启 AI 协同编程时代 |
| **源码文件后缀** | **.jn** 或 **.jenny** | main.jn（极简，键盘右手食指与中指连击，手感极顺滑） |
| **编译器主程序** | **jenny** (或 jennyc) | jenny build、jenny run、jenny debug-meta |
| **包管理器与构建工具** | **spindle**（纱锭） | spindle add http、spindle publish。每一个第三方库或 C 绑定都是一个高速旋转的纱锭 |
| **编译期元编程 DSL** | **@spin** (替代原 @meta) | **“纺纱”即代码生成**！用 @spin fn 将过程式逻辑与 quote 模板纺成目标代码 |
| **元编程落盘镜像目录** | **.spun/**（已纺出的纱线） | 存放所有编译期生成的格式化可读代码（如 .spun/network.jn），供人类审查与打断点调试 |
| **轻量级协程 / 纤维** | **Fiber**（纤维） | 计算机科学中原本就称轻量级用户态线程为 Fiber，在此与纺织主题天然合一 |
| **包配置文件** | **Tapestry.toml** 或 **Jenny.toml** | 意为由无数纱线最终织就的宏伟挂毯（项目工程） |

### **三、 当代码变成“纺纱”：Jenny 语言实战视觉预览**

看看把这套命名融入代码与命令行后，整体散发出怎样的工业美学与诗意：

#### **1\. 终端命令行体验**

```Bash  
# 初始化一个 Jenny 项目  
$ jenny new quantum_engine
# 使用 spindle 引入 C 语言库或社区包  
$ spindle add c:ffmpeg  
$ spindle add std/async
# 先执行编译期“纺纱”(@spin DSL)，检视生成的白盒代码  
$ jenny spin --inspect  
✓ Spun 3 meta-templates into .spun/ directory (0 warnings)

# 编译为 WebAssembly (WasmGC + Linear Memory 双轨模式)  
$ jenny build --target wasm32 -O3
```

#### **2\. main.jn 源码美学展示**

```Rust  
module audio_weaver

import c "samplerate.h" as libsr

// 使用 @spin 定义编译期代码纺锤（原 @meta）  
// 生成的代码会自动落盘到 .spun/audio_weaver.jn 供随时调试  
@spin fn derive_buffer_guard(target: MetaType) -> CodeFragment {  
    return quote {  
        impl $(target.ident()) {  
            pub fn is_valid(&self) -> bool {  
                return self.raw_pcm != null && self.frames > 0  
            }  
        }  
    }  
}

// *AudioChunk 分配在原生堆，与 C 语言零拷贝共享  
@repr(C)  
@apply(derive_buffer_guard)  
pub struct AudioChunk {  
    pub raw_pcm: *f32,  
    pub frames: usize,

    fn drop(mut self) {  
        free(self.raw_pcm)  
    }  
}

// ^TrackNode 分配在 GC 托管堆，轻松构建复杂音频图  
pub struct TrackNode {  
    pub name: String,  
    pub chunk: *AudioChunk,        // 跨堆持有原生音频帧  
    pub next_nodes: []^TrackNode,  // GC 托管引用图  
}

pub fn process_stream(node: &^TrackNode) -> usize ! AudioError {  
    if !node.chunk.is_valid() {  
        raise AudioError.EmptyBuffer  
    }  
    return node.chunk.frames  
}
```
