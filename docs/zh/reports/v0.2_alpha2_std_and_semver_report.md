### 2.2 关键实证发现
1. **白盒化 C 库桥接 (`std::ffi::c_abi` + `spindle bindgen-c`) 终结黑盒 `import c "header.h"` 并实现 $\text{TCR}_{\text{impl}} = 0.1786$**：
   * 在传统语言中，直接导入 C 头文件会将外部依赖变为无法静态审计的黑盒，且 Rust 至今不支持原生 C99 位域（必须在 `#[repr(C)]` 结构体中手写掩码与移位方法 `(self.packed_word0 >> 4) & 0xF`）并要求对所有 `union` 字段读取包裹 `unsafe { ... }`；
   * Jenny 原生支持与 C99 1:1 物理对齐的 `@repr(C) struct` 位域（`@bits(N)`）、`@repr(C) union` 共享内存视图与 `@extern_c("c_symbol")` 白盒绑定，由 `spindle bindgen-c` 自动推导位宽不变式 `invariant self.field >= 0 && self.field <= (2^N - 1)`，使 `std::ffi::c_abi.jn` 仅需 **147 tokens**（vs Rust **823 tokens**，精简 **82.14%**），并在运行期 100% 验证 `c_sizeof_frame(hdr) == 8` 与 `c_sizeof_union(u) == 4`！
2. **Layer-0 运行时内建白盒化 (`std::rt::intrinsics`) 与 `E0510` 静态守卫实战立功**：
   * 通过新增 [`std/rt/intrinsics.jni`](../../std/rt/intrinsics.jni)，将原本散落在 `jenny_rt.h` 中的 22 个 C 运行时原语全部纳入 Jenny 形式化契约体系（含 `40` 条 `requires`/`ensures` 契约与 `effects [Mutate, AllocNative]` 标记）；
   * 在 `spindle audit` 首次开启 `E0510_UNDECLARED_RT_INTRINSIC` 静态扫描时，现场发现并拦截了 `std/collections/hash_map.jn` 的 `contains_key` 绕过 `RawBuf.read_at` 直接调用 `jn_raw_get(self.buf.ptr, ...)` 的隐蔽越权行为，随后重构为调用受契约保护的 `self.buf.read_at(...)!`，实现了 15 个标准库模块的分层白盒严密闭环。
3. **三层正交特征 `Formattable` + 3 分支过程式 `@spin` 模板展开 + 一等元组保留的 `.spun` 落盘 (`std::str::fmt`)**：
   * 通过定义 `pub type Formattable = FmtInto | ToStr | (FmtSpecInto, FmtSpec, ...i64)`，[`std/str/fmt.jn`](../../std/str/fmt.jn) 中的 `format_with` 彻底消除了对 `str`、`String`、`bool`、`i64` 等基础类型的逐个硬编码枚举，仅需 **3 个正交特征分支**（元组 `(val_item, spec, ...params)`、`FmtInto`、`ToStr`）；
   * 展开后的 [`.spun/std_str_fmt.spun.jn`](../../.spun/std_str_fmt.spun.jn) 与全局去重池 `.jenny-cache/spin/format_with__spin_<hash>.spun.jn` 完整保留一等公民元组参数类型（如 `_arg3: (i64, FmtSpec, i64)`），并在函数体内部通过 `_arg3.0`、`_arg3.1`、`_arg3.2` 解构调用，支持将元组存入变量 `val hex_item = (48879, FmtSpec.HexLower, 4)` 后直接传入 `str::format("id=", -42, ",hex=0x", hex_item)`！

## 3. `Spindle` Phase 3, Phase 4, `bindgen-c` & `pack`/`decompile` 颠覆性包管理实测验证

### 3.1 Phase 3：`Tapestry.lock` 双哈希锁定 (`spindle lock`)
[`std/Tapestry.lock`](../../std/Tapestry.lock) 为全部 15 个标准库模块生成了分离的 **接口契约 Merkle 根 (`package_jni_abi_merkle_root`)** 与 **实现代码 Merkle 根 (`package_jn_impl_merkle_root`)**：
* 当任意依赖包仅优化 `.jn` 内部算法而不改变 `.jni` 契约时，`jni_abi_hash` 保持 100% 恒定，下游包无需重新类型检查，直接触发 `.jni` 头文件防火墙短路。

### 3.2 Phase 3：基于契约子类型的语义版本升级验证 (`spindle semver-check`)
传统包管理器（Cargo / npm / Go Modules）依赖人工主观填写的 SemVer 版本号，经常在 `Patch` 小版本中混入隐式前置条件收紧或越权副作用。`spindle semver-check` 基于霍尔逻辑（Hoare Logic）子类型法则：
$$E_{\text{new}} \subseteq E_{\text{old}} \;\land\; (\text{Req}_{\text{old}} \implies \text{Req}_{\text{new}}) \;\land\; (\text{Ens}_{\text{new}} \implies \text{Ens}_{\text{old}})$$
结合 `@example` 差分执行，在 `std::codec::varint` 上完成了 1 项安全热替换验证与 4 项破坏性升级变异拦截：

| 用例 / 变异 ID | 升级场景描述 | `spindle semver-check` 判定分类 | 触发诊断码 | 结果 |
| :--- | :--- | :---: | :---: | :---: |
| **`SAFE-HOT-SWAP`** | 修改 `varint.jn` 中 `zigzag_encode` 内部负数算术实现（不改 `.jni`） | **`SAFE_PATCH_HOT_SWAP`** (`jni_abi_unchanged = true`) | 无 (`compatible = true`) | ✅ 允许免审热替换 |
| **`MUT-SEMVER-E0506`** | 升级版在 `VarintStream.encode_u64` 中新增 `effects [Net]` | **`BREAKING_REJECTED`** | `E0506_SEMVER_EFFECT_EXPANSION` | ✅ 100% 拦截 |
| **`MUT-SEMVER-E0507`** | 升级版将 `requires val >= 0` 收紧为 `requires val >= 10`（破坏传入 `0..9` 的调用方） | **`BREAKING_REJECTED`** | `E0507_SEMVER_STRENGTHENED_REQUIRES` | ✅ 100% 拦截 |
| **`MUT-SEMVER-E0508`** | 升级版删除 `decode_u64` 的后置保证 `&& result >= 0` | **`BREAKING_REJECTED`** | `E0508_SEMVER_WEAKENED_ENSURES` | ✅ 100% 拦截 |
| **`MUT-SEMVER-E0509`** | 升级版保持 `.jni` 不变，但在 `zigzag_encode` 中引入 `val * 2 + 1` 算术退化 | **`BREAKING_REJECTED`** | `E0509_SEMVER_BEHAVIORAL_REGRESSION` | ✅ 100% 拦截 |

### 3.3 Phase 4：纯 `.jni` 蓝图 + 统一 AST 归档分发 (`spindle pack`)、按需无损反编译 (`spindle decompile`) 与蓝图合成 (`spindle synthesize`)
